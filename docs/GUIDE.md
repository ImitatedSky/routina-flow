## 功能

### 手動捷徑 vs 自動化

一個例行程序 = **名稱 +（可選觸發）+ 動作**。這正是 iOS 捷徑的核心區分——
**「捷徑」（手動執行）** 與 **「自動化」（有觸發）**，Routina 同時支援兩者：

- **不設觸發 → 純手動捷徑**：點清單卡片或編輯畫面的 ▶ 就執行（例：開網站、開 App）。
  手動 routine **不排程、不啟動任何監測服務、不耗電**，永遠可用 ▶ 立即執行
- **設了觸發 → 自動化**：符合觸發條件時自動執行，同時仍可隨時點 ▶ 手動執行
- **隨時切換**：點帽子積木開觸發調色盤，把「手動執行」換成定時 / 區域…即變自動化，
  換回「手動執行」即取消排程、回到純手動
- **新建空白 routine 預設就是手動執行**——想做純捷徑時完全不必碰觸發條件；
  範本（早晨 / 就寢 / 到公司 / 回家 / 省電）維持各自的真實觸發不變
- 手動 routine 的**首頁卡片隱藏啟用開關**（沒有可排程的東西，開關無意義），
  以明確的 ▶「執行」為主要操作，狀態晶片顯示中性的「手動」標記、不顯示「下次執行」

| 等待             | 1–30 秒後再執行後續動作                                                    | 流程（灰）       |

| **設定變數**     | 把（可含變數的）文字存成具名變數，後續以 `{{var:名稱}}` 引用，見下         | 變數（藍灰）     |

動作**依加入順序執行，單一動作失敗不會中斷其餘動作**，
每次執行的成敗都會寫入執行紀錄（保留最近 50 筆）。

> **網路安全**：App 透過 network security config 一致封鎖明文 HTTP（含 Android 8.0），
> 因此 **HTTP 請求動作的 webhook 必須使用 https**。若要打區域網路的 http 裝置（例如自架服務），
> 需自行在 `app/src/main/res/xml/network_security_config.xml` 為該網域加上
> `cleartextTrafficPermitted="true"` 的 `domain-config` 例外後重新建置。
>
> **隱私**：執行紀錄（logs.json）會遮罩敏感值——剪貼簿／分享／朗讀文字截斷顯示、
> HTTP 只記去除 query string 後的網址；App 資料一律不隨系統備份或裝置轉移外洩（`allowBackup=false`）。

### 變數與動態參數

文字類動作的參數（通知標題與內容、開啟網址、分享、HTTP 網址與內容、朗讀、剪貼簿、
設定鬧鐘標籤、文字、設定變數）都可以內嵌**變數 token**，執行時即時代入實際值。
在這些欄位下方點「**＋ 插入變數**」會列出當下可用的變數，分四類：

- **觸發提供**：依這個程序的觸發顯示，例如通知觸發有 `{{通知標題}}`、`{{通知內容}}`、
  `{{通知來源App}}`；區域有 `{{地點名稱}}`；NFC 有 `{{標籤名稱}}`；Wi-Fi 有 `{{Wi-Fi名稱}}`；
  藍牙有 `{{藍牙裝置}}`
- **上一個結果**：`{{result}}`＝上一個有輸出的動作留下的內容。目前會產生輸出的動作有
  **HTTP 請求**（2xx 的回應內容）、**拍照 / 連拍 / 錄音**（存檔的 content URI）、**文字**動作
- **已設定的變數**：這個動作之前的「設定變數」動作名稱，以 `{{var:名稱}}` 引用
- **常用**：`{{時間}}`（HH:mm）、`{{日期}}`（yyyy-MM-dd）、`{{星期}}`、`{{電量}}`（0–100）

規則：

- 查不到值（例如定時程序引用 `{{通知內容}}`）代入**空字串**，動作照常執行、不會崩潰
- 不是合法變數的 `{{...}}` 原樣保留
- **不含 token 的純文字完全照舊**——舊資料與純文字動作行為與過去一致，序列化格式不變

範例：

- 收到通知 → 「HTTP 請求」內容填 `{{通知內容}}`，把通知轉發到 webhook
- 「HTTP 請求」抓一段內容 → 下一個「顯示通知」內容填 `{{result}}`
- 「設定變數 問候 = 早安 {{時間}}」→ 之後「顯示通知」內容填 `{{var:問候}}`
- 進入區域 → 通知內容填「你在 {{地點名稱}}，現在 {{時間}}」

> 執行紀錄沿用既有遮罩：代入變數後的分享／朗讀／剪貼簿文字仍會截斷顯示，
> HTTP 網址仍去除 query string，敏感值不會明文落地。

### 執行架構

所有背景觸發（定時、區域、電量、藍牙、Wi-Fi、系統狀態、NFC、通知、App 開啟關閉）
啟動的執行都會交給同一個**短生命週期前景服務**（ExecutionService）：BroadcastReceiver 只有約 10 秒的執行時間，
而等待 / 朗讀 / HTTP 都可能更久，所以動作在服務裡依序跑完後服務立刻自動停止 → 平時零常駐。
多個程序同時被觸發時會排入同一個佇列依序執行，不會互相搶硬體。

系統在極端情況下擋下背景啟動前景服務時，會降級為接收器內直接執行、**跳過等待動作**，
並在執行紀錄中註明降級。手動「立即執行」維持在 App 行程內執行，等待動作照常生效。

### 日出 / 日落觸發

定時觸發除了固定時間，還可以選日出或日落，並加減最多 ±120 分鐘的偏移
（例如「日落後 30 分鐘」）。日出日落以 **NOAA 太陽方程式在本機計算**——
不連網、不需要額外權限、不引入任何函式庫，誤差約 ±2 分鐘。

座標沿用你設定過的任一區域觸發地點（設過「家」或「公司」就等於告訴了 App 大致所在地）；
完全沒有位置資訊時退回預設的 06:00 / 18:00，並在清單畫面顯示提示卡。
每次觸發後都會以「明天的」日出日落時間重新排程。

### 區域觸發（地圖選點）

點編輯畫面的區域參數欄會帶出全螢幕地圖：拖曳地圖讓中央準星對準想要的中心點、
用滑桿調整半徑（100–1000 公尺，步進 50 公尺，圓形範圍即時預覽），
也可以一鍵「使用目前位置」，並替這個地點取個名字（例如「公司」）。

- 圖資用 **OpenStreetMap**（osmdroid），免 API key；圖磚快取放在 App 私有目錄，解除安裝即清除
- 監測交給 **Google Play Services 的系統級地理圍欄**，不自行常駐輪詢 GPS → 低耗電
- 需要「一律允許」的背景位置權限；未授權時不註冊、不觸發，並在首頁顯示引導卡
- 裝置沒有 Google Play 服務時，區域積木在調色盤上以半透明標示為不可用，其他功能不受影響

### 藍牙動作

- **Android 12（含）以下**：直接開啟 / 關閉藍牙
- **Android 13 起**：系統禁止第三方 App 直接切換，改發一則高優先度通知——
  「開啟」點擊後帶出系統的藍牙開啟確認對話框、「關閉」點擊後導向藍牙設定頁；
  執行紀錄的描述會註明「需經系統確認」，**不會記成假成功**

### 剪貼簿動作

把設定好的文字（支援多行）寫入系統剪貼簿，例如「掃床頭標籤就把外送地址複製起來」。

- **手動「立即執行」一律生效**——App 在前景，系統不會擋
- **背景觸發時盡力而為並誠實記錄**：Android 10 起系統只允許前景 App 寫入剪貼簿，
  被擋下時系統不丟例外也不回報，App 端完全無從偵測。因此背景執行照常呼叫、記為成功，
  但執行紀錄的描述會註明「背景寫入在部分裝置可能被系統忽略」，**不會宣稱一定寫進去了**
- Android 13 起系統會顯示「已複製」浮層，可以自己確認是否生效
- 不做「讀取剪貼簿」——Android 10+ 禁止背景讀取，做了也只是假功能

### 拍照 / 連拍 / 錄音（媒體與擷取）

以 **CameraX 無預覽的 `ImageCapture`** 拍照 / 連拍、以 **`MediaRecorder`（MPEG-4 / AAC）** 錄音，
沿用剪貼簿與藍牙的「誠實降級」策略面對系統的相機麥克風限制：

- **手動「立即執行」一律可用**——App 在前景，相機 / 麥克風可正常存取
- **背景觸發時盡力而為並誠實記錄**：Android 9 起禁止背景存取相機與麥克風，
  只有掛上對應 `foregroundServiceType` 的前景服務才能存取；Android 14 起又限制
  「從背景啟動 camera / microphone 類前景服務」。因此背景執行前會把執行服務臨時切換到
  camera / microphone 類型再拍照 / 錄音，做完還原回 specialUse；**被系統擋下時該動作記為失敗
  並註明「背景無法啟動相機 / 麥克風，請改用手動執行或前景觸發」**，後續動作照常執行、不崩潰
- **拍照**：後 / 前鏡頭二選一，存入相簿的 `相片/Routina`（API 29+ 用 MediaStore 免權限；
  API 28 以下寫入公開相簿目錄，需 `WRITE_EXTERNAL_STORAGE`）；無相機硬體或未授權相機時記為失敗並引導授權
- **連拍**：同一次相機綁定內迴圈擷取 2–10 張、每張間隔 200–2000ms（在前景服務的 coroutine 內 delay）
- **錄音**：錄製 1–60 秒，存入 `音樂/Routina`（API 29+ 用 MediaStore；API 28 以下用 App 專屬外部目錄），
  執行紀錄會附上存檔位置；太短或無音源時安靜結束、仍釋放麥克風
- **權限**：加入拍照 / 連拍時就地請求「相機」、加入錄音時就地請求「麥克風」；
  未授權且有這類動作時，首頁會出現引導卡（可一鍵請求）
- **擷取結果通知（可點擊開啟）**：每個擷取動作可開關「完成後發出通知」（預設開）。
  擷取成功後發一則通知（拍照「已拍照」、連拍「已連拍 N 張」、錄音「已錄音 N 秒」，
  內文為檔名），**點通知即以系統檢視器開啟該相片 / 音檔**。點擊開啟需要可跨 App 讀取的
  content URI：API 29+ 直接用 MediaStore 回傳的 URI；API 28 以下用 **FileProvider**
  （authority `${applicationId}.fileprovider`）把檔案轉成 content URI，並帶
  `FLAG_GRANT_READ_URI_PERMISSION` 授權檢視器讀取。連拍的通知開啟最後一張。
  通知走獨立的「擷取結果」channel（可單獨關閉），通知 ID 以流水號遞增，多次擷取彼此不覆蓋；
  未授權通知（Android 13+）時**靜默略過通知，但動作仍記為成功**（檔案已存）

### 設定鬧鐘

以系統時鐘 App 建立一個指定時:分與標籤的鬧鐘，例如「掃床頭標籤就設一個 07:30 的鬧鐘」。

- 用標準的 `AlarmClock.ACTION_SET_ALARM` intent 帶 `EXTRA_HOUR / EXTRA_MINUTES / EXTRA_MESSAGE`，
  並帶 `EXTRA_SKIP_UI`（多數時鐘 App 支援 → 直接新增、不跳確認畫面）
- 沿用「開啟 App / 網址」的背景 Activity 啟動處理：前景直接送出、背景改發一則可點擊的通知
  （點擊後由系統時鐘 App 完成設定）
- 裝置上沒有可處理的時鐘 App 時記為失敗，不崩潰
- `SET_ALARM` 為 normal 權限，安裝時自動授予；無需 runtime 請求

### 分享

跳出系統分享選單（`ACTION_SEND` + `createChooser`）把設定好的文字（連結或任意文字）送出，
由你當下選擇要分享到哪個 App／給誰（LINE、訊息、Email、記事…），
就像 iOS 捷徑的「分享」動作。與**手動 routine** 天然搭配——做一個手動捷徑
「分享今日連結給群組」，點 ▶ 即分享。

- **手動「立即執行」/ App 在前景**：直接跳出系統分享選單
- **背景觸發時的誠實降級**：Android 10+ 系統禁止背景啟動 Activity，
  沿用「開啟 App / 網址」的 `launchOrNotify` 處理——改發一則可點擊的通知
  （走 `CHANNEL_LAUNCH`，`contentIntent` 掛分享選單），**點擊通知才跳出分享選單**，
  執行紀錄註明「已改以通知呈現，點擊分享」，**不會記成假成功**
- **分享文字為空時記為失敗**（無可分享內容），後續動作照常執行；全程 try/catch 不中斷
- 目前只分享文字／連結（分享圖片／檔案需接 content URI，列為後續延伸）；
  不指定固定對象、不略過選擇視窗（Android 不保證可略過 chooser，維持由你當下選擇）
- 無額外權限需求

### 播放音效

播放系統目前設定的預設音效（**通知音 / 鬧鐘聲 / 鈴聲**擇一），以 `RingtoneManager` 實作。

- 無任何額外權限需求；音量跟隨系統對應串流（鈴聲 / 鬧鐘 / 通知）的設定
- 適合當作提示音或搭配其他動作（例如「進公司區域就播一次通知音」）

### Wi-Fi 與藍牙觸發

- **Wi-Fi**：用 `ConnectivityManager` 的網路回呼監測（系統早已停止廣播 Wi-Fi 狀態變化）。
  Android 9 起讀取 SSID 需要精確位置權限——未授權時，**指定了 SSID 的程序不會觸發**
  （寧可不執行也不亂執行），清單畫面會顯示引導卡；改成「任一網路」則完全不需要位置權限
- **藍牙**：`ACL_CONNECTED` / `ACL_DISCONNECTED` 屬於系統隱式廣播的豁免清單，
  可以靜態註冊 → **藍牙觸發不需要任何常駐服務，成本為零**。
  比對依據是裝置位址（不需權限即可讀），只有「已配對裝置清單與名稱」需要
  「附近的裝置」權限；未授權時仍能正常觸發，只是選裝置時只看得到位址

### NFC 標籤觸發

在編輯畫面選「NFC 標籤」會直接帶出掃描對話框：把標籤靠到手機背面即讀入標籤的
識別碼（UID），再替它取個名字（例如「床頭標籤」）就完成登錄。此後只要掃到這張標籤，
對應的例行程序就會執行。

- **登錄只讀 UID，不改動標籤內容**——空白標籤、已寫過網址的標籤都能用
- 掃描對話框開著的期間才啟用讀取模式（reader mode），關閉立刻解除，
  所以登錄中的掃描不會被誤判成「觸發」
- 背景掃描由一個**全透明、讀完就結束的 Activity** 接手：畫面不會閃、不會停在任何新頁面
- 掃到沒登錄過的標籤只顯示一則簡短提示，不執行任何程序
- 裝置沒有 NFC 硬體時，調色盤上的 NFC 積木呈半透明並說明原因；
  NFC 關著時清單畫面會出現引導卡直達 NFC 設定

#### 寫入標籤（選用）——掃描不再跳出 App 選擇視窗

只靠 UID 登錄時，系統是以「標籤技術」把掃描事件派送出去的：裝置上若還裝了其他 NFC App，
掃描時就可能先跳出一個**選擇視窗**問你要用哪個 App 打開。

NFC 標籤對話框下方的「**寫入標籤**」可以把一段 Routina 專屬的識別網址
（`routina://tag/{UID}`）寫進標籤。此後系統以 URI 精準比對，**只有 Routina 符合**，
掃描就會直接執行對應的例行程序，體驗與 iOS 捷徑的 NFC 自動化一致。

- 寫入的同時完成 UID 登錄；**寫入失敗（唯讀、容量不足）時登錄仍然成立**，
  這張標籤照樣能用一般方式觸發
- 未格式化的空白標籤會**自動格式化**後寫入
- 只寫入一段識別網址，**不會改動標籤的硬體 UID**，也不影響已登錄的舊標籤
  （沒寫入過的標籤行為完全不變）
- 失敗情境各有明確訊息：唯讀標籤、容量不足、不支援 NDEF 且不可格式化、
  寫到一半移開（「請保持標籤貼緊再試一次」，可就地重試）

### 通知觸發

指定來源 App（或「任一 App」）發出通知時執行，還可以加關鍵字過濾
（**比對標題與內容，不分大小寫**）。

- 需要「**通知存取權**」，未授權時這些程序不觸發，清單卡片會標示、首頁引導卡直達設定頁
- **Routina 自己發出的通知不會觸發**任何程序（否則「顯示通知」動作會自己觸發自己）
- 忽略常駐型通知（音樂播放器、前景服務）與群組摘要——那些不是「剛剛收到一則通知」
- 同一則通知 5 秒內只觸發一次（App 更新進度、合併群組時通知會被重複送出）
- 監聽服務由系統綁定與啟停，**通知觸發不需要任何常駐服務**

### App 開啟 / 關閉觸發

指定 App 進入前景（開啟）或離開前景（關閉）時執行，例如「打開相機就把音量調到 0」。

- 需要「**使用情況存取權**」（不使用無障礙服務），未授權時不觸發並顯示引導
- 只在（**螢幕亮著**）且（**有這類程序啟用中**）時才輪詢，間隔 3 秒；
  螢幕一熄或程序全部停用就立刻停止 → 不背景耗電
- 同一個 App 持續在前景不會重複觸發，切到別的 App 再回來才會再觸發一次；
  「關閉」的定義就是前景從那個 App 換成別的 App 的那一刻

### 其他

- **圓角色塊積木介面**：觸發條件與動作都是「圓角色塊 + 文字說明 + 白色參數欄」，
  清單卡片內以縮小版唯讀積木堆疊預覽整個流程
- **卡片狀態晶片**：清單卡片名稱下方顯示一列狀態晶片，一眼看出這個程序的近況——
  **下次執行**（定時類算出「今天／明天／週X HH:mm」，含日出日落 + 偏移 + 星期；
  事件類顯示觸發摘要如「進入區域時」，不虛構時間）、**上次結果**（讀最近一筆執行紀錄，
  全成功綠色「上次成功」/ 有失敗琥珀色「上次部分失敗」＋相對時間）、以及**需授權**
  （這個程序所需但未授與的關鍵權限，如「需背景定位」「需通知存取」，點擊直達對應設定頁）。
  晶片用語意色（成功綠／警告琥珀），與品牌主色分離；停用中的程序狀態列一併淡化
- **安全刪除**：編輯畫面的刪除收在右上「⋯」溢位選單裡（紅字），離開返回鍵的相鄰區，
  杜絕誤觸；點選後仍保留刪除前的二次確認。新建（尚未儲存）的程序不顯示刪除選項
- **範本啟動**：空白畫面對新手是最大門檻，所以空狀態改為「從一個範本開始」的 2 欄範本格
  （六選一：早晨 / 就寢 / 到公司 / 回家 / 省電 / 空白），已有程序時 FAB 也帶出同一份範本格
  （「從範本建立 / 空白建立」一鍵可達）。點範本＝建立一份可編輯的新程序（帶預設名稱、
  **預設停用**待你確認），直接進入編輯畫面；範本只是既有觸發／動作的預組合，不新增任何能力。
  需要位置或 Wi-Fi 的範本（到公司 / 回家）套用後會自動帶出選擇器引導你補參數，
  座標未選的區域範本在補齊前無法儲存（沿用既有「未設定不可儲存」機制）
- **拖曳排序動作**：編輯畫面的動作積木可用拖曳改變前後（執行）順序——
  拖積木右側的 **≡ 握把**、或**長按積木本體**都能把它拿起，拿起時積木浮起（陰影＋微放大）
  並給觸覺回饋、其餘積木自動讓位，放開即套用新順序並保存於草稿；
  **單點積木本體＝編輯參數**、**✕＝移除**。觸發帽子積木固定在最上方、不參與排序；
  首頁卡片的縮小預覽維持唯讀、不可拖曳
- **App 圖示**：凡是選擇已安裝 App 的介面（開啟 App 動作、通知觸發、App 開啟／關閉觸發共用同一選擇器）
  都在清單每列前顯示該 App 的圖示，選定後**積木參數欄也在名稱前顯示該 App 的小圖示**，更好辨識。
  圖示以 `PackageManager` 取得、在 IO 執行緒解碼並以 package→ImageBitmap 記憶體快取（不寫檔），
  捲動不重載也不卡頓；任何 App 查不到圖示都 fallback 只顯示名稱，不崩潰
- **顏色只做功能分組**：一組一色相、組內只差色階（觸發：時間靛 / 電源綠 / 連線青 /
  系統與應用藍灰 / 位置紫；動作：通知與 App 藍 / 聲音紅 / 裝置橘 / 媒體與擷取紫 / 流程灰），
  調色盤的分組小標與顏色互相印證；積木文字色自動取白字與深字中對比較高者
- **手動 vs 自動的卡片差異**：手動 routine 的卡片只有明確的 ▶「執行」（隱藏啟用開關——
  沒有可排程的東西）；具自動觸發的 routine 維持啟用開關與「立即執行」按鈕，
  立即執行對所有 routine 一律可用、不受啟用狀態限制
- 開機後自動恢復所有排程、地理圍欄與監測（地理圍欄會被系統在重開機時清除，必須重新註冊）
- 電量 / Wi-Fi / 飛航 / 勿擾 / 省電 / App 開啟關閉類例行程序全部停用時，
  背景監測服務自動停止 → 平時零常駐

| `NFC`                                                          | 讀取 NFC 標籤的識別碼（UID）以比對 NFC 觸發，以及選用的「寫入標籤」                  | 安裝時自動授予；`uses-feature required=false`，無 NFC 硬體照樣可安裝                                  |
| `PACKAGE_USAGE_STATS`                                          | App 開啟／關閉觸發（讀使用情況判斷前景 App）                                         | 特殊權限，需手動到「具有使用權限的應用程式」開啟；未授權時該類程序不觸發                              |
| `BIND_NOTIFICATION_LISTENER_SERVICE`                           | 通知觸發（由系統綁定通知監聽服務）                                                   | 服務宣告用；實際開關是「通知存取權」，需手動授權                                                      |
| `<queries>` MAIN/LAUNCHER                                      | 列出可啟動的 App 供「開啟 App」動作、通知觸發與 App 觸發選擇                         | Android 11+ 套件可見性宣告，非執行階段權限                                                            |

### 需要手動授權的幾項

- **鬧鐘與提醒**（Android 12+）：未授權時，清單畫面上方會出現提示卡片，點擊直接跳到設定頁。
- **勿擾模式存取權**：切換響鈴模式為靜音 / 震動、切換勿擾模式，以及勿擾下調整鈴聲／通知音量時需要。
  執行時若未授權，會發一則可點擊跳轉設定的通知，該動作記為失敗但不影響其他動作。
- **修改系統設定**：只有「螢幕亮度」動作需要。未授權時該動作記為失敗並發引導通知，
  清單畫面與動作編輯對話框也都有直達設定頁的按鈕。
- **顯示在其他應用程式上層**：只有在「開啟 App / 開啟網址」需要由背景觸發時才需要。
  未授權時不會失敗，而是改發一則可點擊開啟目標的通知；清單畫面也會出現提示卡片。
- **位置「一律允許」**：只有區域觸發需要。Android 11 起系統不允許 App 直接請求背景位置，
  只能由你到 **設定 > 應用程式 > Routina > 權限 > 位置** 選「一律允許」；
  編輯畫面與清單畫面都有引導卡可直達，授權後回到 App 會自動註冊地理圍欄。
- **精確位置**（前景）：指定 SSID 的 Wi-Fi 觸發需要（Android 9 起讀 SSID 的系統限制）。
  未授權時這類程序不會觸發，清單畫面會顯示引導卡；改成「任一網路」則不需要。
- **附近的裝置**（Android 12+）：藍牙動作、以及藍牙觸發要挑選特定裝置時需要。
  藍牙觸發只用位址比對，未授權也能正常觸發。
- **通知存取權**：只有通知觸發需要。未授權時系統根本不會啟動監聽服務，這類程序不會觸發；
  清單卡片會標示、首頁引導卡可直達（Android 11 起會直接開到 Routina 那一列開關）。
  側載安裝時開關可能呈灰色，處理方式與「顯示在其他應用程式上層」相同，
  見[疑難排解](#疑難排解)。
- **使用情況存取權**：只有 App 開啟／關閉觸發需要，**不使用無障礙服務**。
  未授權時不觸發並顯示引導卡；已授權後也只在螢幕亮著且有這類程序啟用時才輪詢。

## 疑難排解

### 權限開關是灰色的，按不下去（疊加權限、通知存取權）

以 APK 直接安裝（側載）時，**Android 13+ 會用「受限制的設定」（Restricted settings）
鎖住高風險權限**，例如「顯示在其他應用程式上層」、「通知存取權」與無障礙服務。
這是系統對非商店來源 App 的安全機制，不是 Routina 或該權限頁面壞掉。

解法（已在 Pixel 10 實測成功）：

1. **設定** > **應用程式** > **查看所有應用程式**
2. 找到並點進 **Routina**
3. 點右上角的 **三點選單（⋮）**
4. 選 **允許受限制的設定**
5. 依提示**驗證身分**（螢幕鎖定的 PIN / 指紋 / 臉部辨識）
6. 返回權限頁面，此時開關已可正常開啟

完成授權後回到 Routina，清單上方的提示卡片會自動消失
（App 每次回到前景都會重新檢查權限狀態）。

### 授權後提示卡片還在？

切回 Routina 主畫面即會重新檢查；若仍顯示，代表權限實際上沒有授權成功，
請依上述步驟確認「允許受限制的設定」已完成。

### 區域程序沒有觸發

依序確認：

1. 清單畫面上方沒有位置相關的提示卡片（有的話點進去把權限改成「一律允許」）
2. 系統的定位服務已開啟，且 **設定 > 位置 > 位置服務 > Google 位置精確度** 為開啟
   （地理圍欄靠 Wi-Fi / 行動網路輔助定位，只用 GPS 會很不靈敏）
3. 半徑不要設得太小——系統建議至少 100 公尺，市區建議 200 公尺以上
4. 地理圍欄由系統排程回報，**進出區域到實際觸發之間可能有數分鐘延遲**，這是系統行為

裝置若沒有 Google Play 服務（例如部分中國市場機型），區域觸發無法使用，
調色盤上的區域積木會呈半透明並說明原因。

### NFC 標籤掃不到 / 掃到卻沒反應

依序確認：

1. 首頁上方沒有「NFC 已關閉」的提示卡（有的話點進去開啟 NFC）
2. 標籤靠的位置對不對——多數機型的 NFC 天線在機背鏡頭附近，貼著慢慢移動找位置
3. 標籤是不是**登錄的那一張**：程序卡片上的標籤名稱就是登錄時取的名字，
   掃到別的標籤會顯示「還沒登錄」的提示
4. 螢幕要亮著且已解鎖（系統只在此時派送 NFC 掃描）

### 掃描標籤時跳出「用哪個 App 打開」的選擇視窗

裝置上還裝了其他 NFC App 時，系統會問你要用哪一個處理這張標籤。
在編輯畫面的 NFC 標籤對話框點「**寫入標籤**」把 Routina 專屬的識別網址寫進標籤，
之後掃描就只有 Routina 符合，選擇視窗不會再出現。

### 通知 / App 程序沒有觸發

- **通知觸發**：確認已授權「通知存取權」（首頁引導卡可直達）。
  常駐通知（音樂播放器）與群組摘要會被刻意忽略；關鍵字是比對標題與內容的「包含」，
  不是完整比對。
- **App 開啟／關閉**：確認已授權「使用情況存取權」。偵測只在螢幕亮著時進行，
  且每 3 秒才查一次，所以開啟 App 到執行之間可能有幾秒延遲。

### 定時程序沒有準時觸發

確認已授權「鬧鐘與提醒」（清單上方的提示卡片可直接跳轉）。
未授權時系統只保證 ±10 分鐘的時間窗；部分機型的電池最佳化也會延後喚醒，
可在系統設定將 Routina 設為「不受限制」。

## 技術架構

| 面向                | 選擇                                                                                                                                                  |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| 語言 / UI           | Kotlin 2.0.21、Jetpack Compose + Material 3                                                                                                           |
| 儲存                | kotlinx.serialization JSON（App 私有 `filesDir`），無資料庫                                                                                           |
| 定時觸發            | `AlarmManager` single-shot chain（觸發後排下一次）                                                                                                    |
| 日出 / 日落         | NOAA 太陽方程式純函式本地計算（`SunCalc`），無依賴、不連網                                                                                            |
| 電量 / 系統狀態觸發 | 前景服務 + 動態註冊 `BroadcastReceiver`                                                                                                               |
| Wi-Fi 觸發          | `ConnectivityManager.registerNetworkCallback`（SSID 取自 `NetworkCapabilities.transportInfo`）                                                        |
| 藍牙觸發            | manifest 靜態 `ACL_CONNECTED` / `ACL_DISCONNECTED` receiver（隱式廣播豁免，零常駐）                                                                   |
| 區域觸發            | Play Services `GeofencingClient`（系統級地理圍欄，低耗電）                                                                                            |
| NFC 觸發            | `TECH_DISCOVERED`（+ `NDEF_DISCOVERED` 備援與 `routina://tag` 專屬 filter）dispatch 到透明的 `NfcDispatchActivity`；登錄／寫入都用 `enableReaderMode` |
| NFC 寫入            | `Ndef.writeNdefMessage`（可寫與容量檢查）／未格式化標籤用 `NdefFormatable.format`，內容為 `NdefRecord.createUri`                                      |
| 通知觸發            | `NotificationListenerService`（系統綁定、零常駐）＋ notification key 5 秒去重                                                                         |
| App 觸發            | `UsageStatsManager.queryEvents` 前景事件，`MonitorService` 內 3 秒輪詢，SCREEN_ON/OFF 控制啟停                                                        |
| 動作執行            | 短生命週期前景服務 `ExecutionService`（佇列化、跑完自停），失敗降級為接收器內執行                                                                     |
| 拍照 / 連拍         | CameraX 1.4.2 無預覽 `ImageCapture`（服務內自建 `LifecycleRegistry` 當 owner），存 MediaStore；背景以 camera 類 FGS 把關                              |
| 錄音                | `MediaRecorder`（MPEG-4 / AAC）錄 N 秒存 MediaStore / App 外部目錄；背景以 microphone 類 FGS 把關                                                     |
| 播放音效 / 設定鬧鐘 | `RingtoneManager` 播系統預設音效／`AlarmClock.ACTION_SET_ALARM` intent（SKIP_UI，沿用背景 Activity 啟動處理）                                         |
| HTTP / TTS          | `HttpURLConnection`（10 秒逾時）／`TextToSpeech` 單例惰性初始化，皆無第三方依賴                                                                       |
| 地圖                | osmdroid 6.1.20 + OpenStreetMap 圖資（免 API key）                                                                                                    |
| 動作拖曳排序        | `sh.calvin.reorderable` 2.5.1 的 `ReorderableColumn`（非 lazy，與編輯畫面可捲動 Column 相容，免巢狀捲動）                                             |
| 架構                | 單一 Activity + Compose Navigation、手寫單例 Repository + ViewModel（無 DI 框架）                                                                     |
| 建置                | AGP 8.7.3 / Gradle 8.10.2、R8 minify + resource shrinking                                                                                             |
