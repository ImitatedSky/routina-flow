# Change: add-numeric-params

## Why

使用者回饋「真正相容各種參數」的具體例子：連拍張數現在是**滑桿、上限 10 張**，
但實際情境可能要 20、135、37 張。數值型參數不該被小上限的滑桿綁死，應該能：

1. **直接鍵入任意數字**（在合理安全上限內）
2. **使用數字變數**（如 `{{var:張數}}`、`{{電量}}`），執行時解析成數字

這是變數系統 Wave 2 的「數字」切片：把動作的數值參數變成「數字或變數」。

## What Changes

- 動作的數值參數改成**數字輸入欄 + 「插入變數」**（不再只有小範圍滑桿）：
  可直接打任意整數，或插入解析後為數字的變數 token
- 涵蓋這些**動作**參數（皆在執行時有 RunContext，可解析變數）：
  - 連拍：張數、間隔（ms）
  - 等待：秒數
  - 震動：毫秒
  - 錄音：秒數
  - 音量：百分比
  - 螢幕亮度：百分比
- **安全上限（clamp）**：解析後夾在各參數的安全範圍內，避免荒謬/危險值
  （例：連拍 1–999、等待 1–3600 秒、震動 1–10000ms、錄音 1–3600 秒、音量/亮度 0–100）
- **向後相容**：既有的數值欄（Int）保留；新增選用的「運算式」字串欄，
  非空時於執行時解析（數字或變數 token）覆寫，空則沿用原本 Int（舊資料零影響）
- 觸發類的數值（電量門檻、區域半徑）**不在本次**：門檻在背景監測評估、非執行期，
  沒有 RunContext 可解析變數；其範圍（0–100 / 100–1000m）本就是實際限制，維持滑桿

## Non-goals

- 完整的數字/數學處理動作（加減乘除、四捨五入…）——變數 Wave 2 的其餘部分，另議
- 觸發門檻用變數（無執行情境，語意不成立）
- 型別化 VarValue（本次數字仍以字串承載、執行時 parse）

## Impact

- 受影響 specs：routine-actions（數值參數語意擴充）、routine-variables（數字變數解析）
- 受影響程式碼：model（上述動作各加一個選用 `xxxExpr: String = ""`）、
  engine（RoutineExecutor 解析 expr→變數代入→parse Int→clamp，失敗 fallback 原 Int）、
  ui（數值參數編輯器改為數字輸入欄 + 插入變數；保留滑桿為快速調整）
- 無新增依賴；versionName 0.15.0 / versionCode 15
