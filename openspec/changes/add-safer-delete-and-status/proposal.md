# Change: add-safer-delete-and-status

## Why

UI/UX 檢視的 P0 前兩項（安全與線索）：
1. **刪除鈕太容易誤觸**（Critical）——編輯畫面右上角垃圾桶緊鄰返回鍵，操作時屢次誤按跳出刪除確認框，對一般使用者是實質資料遺失風險。
2. **卡片缺乏狀態線索**（High）——首頁卡片看不出「下次何時執行」「上次成功了嗎」「缺哪個權限」，使用者無法信任它在背景運作。

## What Changes

### 安全刪除
- 編輯畫面**移除頂部列的垃圾桶圖示**，改在右上「⋯」溢位選單內提供「刪除例行程序」（紅字），
  保留既有二次確認對話框
- 溢位選單同時容納「重新命名」與未來項目的擴充空間（本次先放刪除；重新命名沿用名稱欄即可，
  不重複做）

### 卡片狀態晶片
- 首頁每張卡片名稱下方加一列狀態晶片（依情況顯示，最多три項）：
  - **下次執行**：定時／日出日落類顯示「明天 08:00」「今天 18:50」等；事件類（充電/區域/藍牙…）
    顯示觸發條件摘要（如「進入區域時」）
  - **上次結果**：讀執行紀錄最近一筆——「✓ 上次成功」「✕ 上次部分失敗」＋相對時間（如「2 小時前」）
  - **需授權**：該 routine 依其觸發/動作所需但未授與的權限（背景定位、通知存取、使用情況、
    精確鬧鐘、勿擾、相機…）以警告色晶片提示，點擊導向對應設定（沿用既有引導）
- 晶片用語意色（成功綠／警告琥珀），與品牌主色分離；停用中的 routine 狀態列淡化

## Non-goals

- 品牌識別、底部分頁、抽屜化編輯（屬 P1，另案）
- 精準到分鐘的倒數計時（下次執行顯示到時刻即可，不做即時 tick）
- 重寫權限系統（沿用既有各權限檢查，只是彙整成卡片晶片）

## Impact

- 受影響 specs：routine-management（清單卡片狀態、編輯畫面刪除位置 MODIFIED 精神，以 ADDED 表述）
- 受影響程式碼：ui\HomeScreen.kt（卡片狀態列、溢位選單非此檔）、ui\EditScreen.kt（頂部列改 ⋯ 選單）、
  engine\AlarmScheduler（計算下次執行時間的共用函式，唯讀查詢不改排程邏輯）、
  可能新增 ui 小工具彙整「所需但未授權」清單
- 無新增依賴；versionName 0.9.0 / versionCode 9
