# Change: add-variables

## Why

使用者要「真正相容各種參數，讓 Routina 有更多可能」，方向對齊 iOS 捷徑的**變數系統**：
動作能吃到動態資料——前一個動作的輸出、觸發帶來的資訊、以及使用者自訂的變數，
而不是只能填死的靜態文字。例如：

- 拍照 → 把「剛拍的照片」分享出去
- 取得 URL 內容（HTTP）→ 用回應內容發通知
- 收到通知 → 把「通知內容」HTTP 送到 webhook
- 進入區域 → 通知顯示「你在 {地點名稱}，現在 {時間}」

這是架構級的能力，會**分波實作**；本 change 建立**基礎（Wave 1）**並在 design.md 定出後續路線。

## What Changes（Wave 1：變數基礎 + 動態參數）

- **執行情境（RunContext）**：一次執行過程中攜帶「變數表 + 觸發情境 + 上一個動作輸出」，
  在動作間流動
- **魔術變數（動作輸出）**：每個動作執行後可產生一個輸出值，後續動作可引用（如 HTTP 的回應、拍照的檔案）
- **觸發情境值**：觸發把可用資訊放進情境——通知觸發的「通知標題/內容」、電量、Wi-Fi 名稱、
  觸發時間、NFC 標籤名稱、區域名稱等
- **文字參數可插入變數**：通知標題/內容、分享、HTTP 網址/內容、朗讀、剪貼簿等文字欄，
  可插入 token（如 `{{result}}`、`{{var:名稱}}`、`{{電量}}`、`{{時間}}`、`{{通知內容}}`），
  執行時即時代入；**沒有 token 的舊資料完全照舊**（純文字），序列化格式不破壞
- **變數插入 UI**：文字參數編輯器加「插入變數」，列出當下可用的變數（觸發提供的、
  之前動作的輸出、已設定的變數）
- **新動作**：`設定變數`（把一段（可含 token 的）文字存成具名變數）、`文字`（產生一段文字輸出當作後續引用來源）

## Non-goals（本波不做，列於路線圖）

- **控制流程（如果 / 重複）**——需要把「扁平動作清單」改成可巢狀結構，屬後續大波（見 design.md）
- 完整資料型別與處理動作（列表 / 辭典 / 數字數學 / 日期運算）——Wave 2 起逐步加
- 變成 Tasker：仍守「觸發 → 依序動作」的心智；變數是讓動作更靈活，不是引入完整程式語言

## Impact

- 受影響 specs：新增 capability `routine-variables`（Wave 1 需求）；routine-actions 既有文字動作
  參數語意擴充（可含變數 token，向後相容）
- 受影響程式碼：model（新增 SetVariable / Text 動作；文字欄語意不變仍是 String）、
  engine（RunContext、token 解析器 VariableResolver、RoutineExecutor 執行時代入、各觸發填入情境值、
  動作回傳輸出）、ui（文字參數編輯器的變數插入器、調色盤新增「變數」分組）
- 無新增第三方依賴；versionName 0.14.0 起（各 wave 各自一版）
