# routine-variables（變數與動態參數）

## ADDED Requirements

### Requirement: 執行情境與魔術變數
系統 SHALL 在每次例行程序執行時建立一個執行情境，攜帶具名變數表、觸發情境值、以及「上一個動作的輸出」，並貫穿該次所有動作。每個動作 SHALL 可讀取情境，且可選擇產生一段輸出寫入「上一個動作的輸出」，供後續動作引用。

#### Scenario: 上一個動作的輸出被引用
- **WHEN** 一個「HTTP 請求」動作之後接一個「顯示通知」，通知內容含 `{{result}}`
- **THEN** 通知內容代入 HTTP 回應內容

#### Scenario: 無輸出動作不覆寫
- **WHEN** 某個動作沒有輸出（例如震動）
- **THEN** 「上一個動作的輸出」維持前一個有輸出動作的值

### Requirement: 觸發情境值
觸發啟動執行時 SHALL 把可用資訊放入執行情境（如通知觸發的通知標題/內容、電量、Wi-Fi 名稱、地點名稱、NFC 標籤名稱，以及所有執行皆有的時間/日期）。文字參數引用了當次觸發未提供的值時 SHALL 代入空字串，不得崩潰。

#### Scenario: 通知內容轉發
- **WHEN** 通知觸發的程序有一個「HTTP 請求」動作，其內容含 `{{通知內容}}`
- **THEN** 送出的內容代入該通知的內容

#### Scenario: 引用不存在的觸發值
- **WHEN** 定時觸發的程序引用 `{{通知內容}}`
- **THEN** 代入空字串，動作照常執行

### Requirement: 文字參數插入變數
文字類動作參數（通知標題與內容、分享、HTTP 網址與內容、朗讀、剪貼簿、設定鬧鐘訊息等）SHALL 支援內嵌變數 token，於執行時即時代入實際值；**不含 token 的既有純文字 SHALL 原樣輸出**，序列化格式不得變更。編輯器 SHALL 提供「插入變數」入口，列出當下可用的 token（觸發提供的、上一個結果、已設定的變數、常用時間/日期等）。

#### Scenario: 插入並代入
- **WHEN** 使用者在通知內容插入 `{{時間}}` 與 `{{電量}}` 並執行
- **THEN** 通知顯示當下時間與電量

#### Scenario: 舊資料相容
- **WHEN** 執行一個在此功能之前建立、內容為純文字「早安」的通知動作
- **THEN** 通知顯示「早安」，行為與過去完全一致

### Requirement: 變數動作
系統 SHALL 提供「設定變數」動作（把一段可含 token 的文字解析後存成具名變數，供後續以 `{{var:名稱}}` 引用）與「文字」動作（把一段可含 token 的文字設為輸出，作為資料來源）。

#### Scenario: 設定並引用變數
- **WHEN** 程序先「設定變數 問候 = 早安 {{時間}}」，之後「顯示通知」內容為 `{{var:問候}}`
- **THEN** 通知顯示「早安 」加上當下時間
